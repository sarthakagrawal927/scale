Critical/high-priority findings:
1. Unnamed responsive navigation buttons. App.tsx:152 gives nav buttons no aria-label; styles.css max-width:1020 hides .nav-item>span with display:none. Icon-only tablet navigation loses textual accessible names. At max-width:600, the laboratory label remains hidden. Add persistent aria-labels and aria-current/pressed semantics. Modal at App.tsx:173 also lacks aria-labelledby/aria-label; visible heading is not a dialog accessible name automatically.
2. Concurrent tabs can overwrite company progress. App.tsx:33-40 writes scale.company.v1 every three seconds and pagehide, with no ownership lock, version comparison, storage listener, or conflict UI. Each tab has its own worker and independently advanced company. Closing an older tab can overwrite a newer session's project/progress. Browser inventory already showed two Scale tabs on the same origin; no destructive reproduction was attempted.
3. Storage failure is invisible on phones. All save errors/unreadable-save warnings only appear in .local-save (App.tsx:151); max-width:600 sets .local-save display:none. A phone user can keep playing while no progress can be retained without seeing a warning. Keep failure states in an always-visible role=status/alert surface.
4. Sandbox freeze does not survive close/reopen. runtime.ts:93 suspends by sandbox presence, leaving company.paused unchanged. App.tsx saves only company. A company that was running at branch time is saved as running; reload drops sandbox and advances offline company time. Either persist a frozen save explicitly with resume intent, or clearly disclose that sandbox freeze is session-only. This is inferred directly from serialization/constructor behavior, not interactively tested.

Other material findings:
- Readability is weaker than the workbench promise: much operational text is 8–10 CSS px, with chart footnotes reaching 7px on phones. Nodes are additionally scaled down to fit, making their metadata smaller still. Zoom exists, but node reading/selection should not depend on precision interaction.
- Phone controls often remain 30–40px, including 30px canvas tools and 30px transport. The large touch-action:none canvas blocks normal touch scrolling over a substantial phone region. Responsive visual verification remains needed.
- Corrupt-save protection is helpful but permanent for the session: protectSave is captured during mount. Explicit Start a new company resets the worker but cannot clear this flag, so the replacement company is not persisted. An explicit recovery flow should allow replacement after confirmation while preserving an export/backup.
- Sandbox traffic slider records history and rebuilds/warms the engine on every input event (160 simulation advances each warm). Rapid scrubbing can queue expensive work and makes undo step through slider ticks. Worker isolation protects main-thread computation but command latency may still be poor. Batch/coalesce traffic previews and record one undo entry per committed gesture.
- Native progress elements lack accessible labels; speed and selected navigation states rely on classes only. Component node buttons and zoom controls do have useful aria labels; node pressed state and decision disclosure expanded state are present.
- Tokens and reduced-motion fallback are strong foundations. Numerous literal colors remain beyond declared tokens; DESIGN.md says system sans but implementation loads DM Sans and Manrope. Resolve the design-doc mismatch. No dark theme was required, so absence was not treated as a failure.
- Positive integrity foundations: simulation is worker-owned, save schema validation exists, unreadable saves are preserved, offline progress is capped, expenditures are checked in runtime, sandbox copies architecture and resets deterministic seeds, undo/redo histories are bounded.
